1. 概览

┌─────────────────────┐ POST /start (REST) ┌─────────────────────┐ │ Frontend │ ───────────────────────────────► │ Backend │ │ (EventSource) │ │ PipelineRunner │ │ │ ◄─────────────────────────────── │ + EventBus │ │ │ SSE: data: {json}\n\n │ │ │ │ pipeline_started │ Step Executors │ │ │ emit_progress │ emit 19 种事件类型 │ │ │ step_complete └─────────────────────┘ │ │ portrait_image_status │ │ ... └─────────────────────┘

SSE 是单向协议（后端 → 前端）。所有客户端到后端的操作（启动、暂停、取消、重试）通过 REST API 完成。

后端组件：

  • EventBus — 进程内发布/订阅，每个 project_id 维护一个订阅者队列列表
  • EventEmitter — 带类型的发布辅助类，step executor 通过它发送事件
  • sse_encode(event) — 将事件 dict 格式化为 data: {json}\n\n 帧

事件连接生命周期：

// 前端连接
const es = new EventSource(`${BASE}/api/projects/${pid}/pipeline/events`)

es.onmessage = (e) => {
  const event = JSON.parse(e.data)
  handleEvent(event)
}

// 断开时 3 秒后自动重连
es.onerror = () => {
  es.close()
  setTimeout(connect, 3000)
}

5. 前端事件路由

前端 usePipelineSSE hook 的 handleEvent(event) 方法按事件类型执行不同操作：

事件类型路由说明
emit_progress 本地合并 直接更新 React state 中的进度值，不请求后端
pipeline_completed 本地合并 设置 pipeline_status='completed'
pipeline_failed 本地合并 设置 pipeline_status='failed', pipeline_error
pipeline_started fetchStatus() 触发完整状态拉取
pipeline_paused fetchStatus() 触发完整状态拉取
pipeline_resumed fetchStatus() 触发完整状态拉取
pipeline_cancelled fetchStatus() 触发完整状态拉取
step_start fetchStatus() 触发完整状态拉取
step_complete fetchStatus() 触发完整状态拉取，随后触发 getProject() 拉取业务数据
step_failed fetchStatus() 触发完整状态拉取
portrait_image_status onEvent() 直接回调，实时更新角色肖像状态
storyboard_scene_ready onEvent() 直接回调，触发场景数据刷新
shot_frame_ready onEvent() 直接回调
shot_video_ready onEvent() 直接回调
scene_composite_ready onEvent() 直接回调
final_video_ready onEvent() 直接回调，显示最终视频
task_status onEvent() 直接回调

6. 一致性与重连策略

  • SQLite 是最终真相源。前端从不单独信任 SSE 事件的内容——所有非进度事件都会触发 fetchStatus() 从 SQLite 读取全量状态。
  • 进度事件是易失的。emit_progress 只存在于 React state 中。如果客户端断开后重连，缺失的进度事件不会导致不一致——下一个 step_complete + fetchStatus() 会补全所有信息。
  • 页面刷新。usePipelineSSE 在挂载时立即调用 fetchStatus()，即使没有收到任何 SSE 事件，UI 也能显示正确的状态。
  • 业务事件暂存。portrait_image_status 等事件可能在角色数据加载前到达，前端使用 pendingPortraitEventsRef 缓存起来，待数据就绪后回放。
  • SSE 重连。浏览器原生 EventSource 在断开后自动重连，前端另加 3 秒容错。重连后下一个事件触发 fetchStatus() 填补空白。
